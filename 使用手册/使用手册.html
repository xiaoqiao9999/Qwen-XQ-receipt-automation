① 快速上手

日常三步

  1. 把待处理文件直接丢进 10_输入 根目录——入库单扫描件（jpg/png）、发票、申购单、事项审批混放都行，程序启动时会自动分拣归位（识别不了的进 10_输入\待确认 并提示，不会丢文件）。当然，习惯手动放子目录也完全可以，程序不会动它们
  2. 双击根目录的 一键生成.bat（或在命令行运行 python run.py）
  3. 到 30_待打印 取 PDF、20_输出 取台账和 Word 成品
成品位置约定：台账 → 20_输出\台账；验收单 Word → 20_输出\验收单；打印用 PDF → 30_待打印（2026-09-06 起统一此口径）；付款单 → 20_输出\付款单；处理完的原件自动归档到 40_归档。

内置的安全校验

  • 交叉验证：每行「数量 × 单价 = 金额」、各行合计 = 单据合计，不一致只打 WARNING，绝不自动改数；
  • 台账自检（步骤4.5）：台账与数据库逐单号比对行数与金额，整单缺失自动补入，补不了才提示人工；
  • 用途不一致熔断：同一金额的申购单与事项审批用途冲突时，放弃自动采用并在结尾集中列出，等人工核对；
  • 幂等防重：已入账单号、已处理发票会自动跳过，重复运行不产生重复记录。

⑤ 数据维护与安全

备份三件套

  • 数据库：60_数据\单据.db 单文件，定期复制一份即为备份；
  • 原件：40_归档 里的扫描件/发票是不可再生的凭证，删项目前务必单独备份；
  • 模板：50_模板 含公司表单样式，建议纳入网盘/版本库。

手工补录一张入库单

python 80_工具\manage_db.py add CGSH单号        # 交互式逐项录入（单号形如 CGSH + 12位数字）
python run.py                                            # 补录后重跑，台账/验收单自动补齐

修正识别错误

OCR 结果缓存在 90_临时\ocr_cache\<图片MD5>.txt，格式为「一行一个字段」。图清晰但识别错时：先删对应缓存让引擎重跑，或对照原图手工改缓存文件（严禁凭记忆改数字），再运行 rebuild_outputs.py 重建成品。

⑥ 常见问题

Q1：双击 bat 报 ModuleNotFoundError？

本机的 python 命令可能解析到没装依赖的内置运行时。始终用 python run.py 或 一键生成.bat 启动，它会自动探测并切到装齐依赖的解释器。

Q2：验收单没有 PDF？

若跑批时设过 SKIP_PDF=1 或 Word 组件被占用，docx 已生成但 PDF 被跳过。关闭所有 Word 窗口后运行 python 80_工具\to_pdf.py 补转，PDF 统一落在 30_待打印。

Q3：台账金额和发票对不上？

先看运行输出里的 WARNING（交叉验证/台账自检都会点名单号）；再用 manage_db.py show 单号 核数据库；最后对照 40_归档 原图人工确认。以票面原图为准，改库后 rebuild_outputs.py 重建。

Q4：重复运行会不会把台账写重？

不会。台账按入库单号去重（已有单号跳过），发票按 processed 标记去重，扫描件处理完即移出输入目录。

Q5：项目目录搬家了要改代码吗？

不用。paths.py 按自身位置自动定位根目录；若想「代码和数据分开放」，设置环境变量 DJ_BASE 指向数据根目录即可。

Q6：误删了文件怎么办？

本手册的清理操作一律走 回收站（右键 → 还原即可）；脚本运行只移动、重命名文件，不删除原件——处理完的原件都在 40_归档。
